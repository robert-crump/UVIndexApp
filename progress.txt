## Issue #6 — Notification module foundation + Daily Forecast channel

### Status: COMPLETE

### What was implemented

**New package `com.uvindex.app.notification`:**

- `NotificationTypes.kt` — Decision-locked data types: `NotificationHistory`, `WarnedAbout`,
  `Channel`, `Phase`, `Priority`, `Action`, `NotificationDecision`. No Android imports.

- `NotificationDecider.kt` — Pure `decide(now: ZonedDateTime, forecast: UVForecast?,
  history: NotificationHistory): List<NotificationDecision>` function. No Android imports.
  Morning trigger window: hours 5–11. Emits Daily decision when `dailyEnabled`, not already
  sent today, in window, and forecast available. UV Warning channel returns nothing (Slice 2).

- `NotificationHistoryStore.kt` — `NotificationHistoryStore` interface with
  `snapshot() / record() / markUvWarningDisabledToday()`. Backed by
  `SharedPreferencesNotificationHistoryStore` which runs one-time migration from legacy
  `uv_notifications` and `uv_app_settings` SharedPreferences on first `snapshot()` call.
  Migration flag: `umbrella_migrated` in `uv_notification_history` prefs.

- `NotificationDispatcher.kt` — Renders a `NotificationDecision` into an Android notification.
  Returns `true` on success, `false` (no crash) when POST_NOTIFICATIONS permission is missing.

**Refactored `DailyUVCheckWorker.kt`:**
- Reduced to: refresh forecast → snapshot history → decide() → dispatch + record on success.
- Inline helpers `sendDailyForecastNotification`, `buildDailyDescription`, `createTimeRanges`,
  `formatTimeRange` deleted from the worker.

**Test infrastructure (`app/src/test/java/`):**
- Scaffolded JVM test source set (previously empty).
- `NotificationDeciderTest` — 6 pure JVM tests for `decide()` Daily cases.
- `NotificationHistoryStoreTest` — 4 Robolectric tests covering migration from legacy keys.
- `NotificationDispatcherTest` — 2 Robolectric tests verifying correct notification ID/title/body
  and graceful false-return when permission missing.

**Build upgrades required for JDK 25 compatibility:**
- Gradle wrapper: 8.2 → 9.5.1 (Gradle 8.x embeds Kotlin 2.0.21 DSL which can't parse JDK 25
  version string; Gradle 9.5.1 embeds Kotlin 2.1.x DSL with the fix).
- Kotlin plugin: 1.9.22 → 2.1.21 (via `org.jetbrains.kotlin.android` + new
  `org.jetbrains.kotlin.plugin.compose` plugin replacing `composeOptions` block).
- AGP: 8.2.2 → 8.7.3 (needed for Gradle 9.x compatibility).
- Robolectric: 4.11.1 → 4.16.1 (4.14.x and earlier use ASM < 9.8 which can't read JDK 25
  class file major version 69; 4.16.1 includes ASM 9.8 with JDK 25 support).
- Serialization plugin: 1.9.22 → 2.1.21.

**Test pattern note (for future slices):**
Robolectric tests: annotate with `@RunWith(RobolectricTestRunner::class)` + use
`@Config(application = Application::class)` to prevent `UVIndexApplication.onCreate()` from
running (it calls WorkManager which is not initialized in Robolectric test environment).
Obtain context via `ApplicationProvider.getApplicationContext()`.

## Issue #7 — UV Warning channel with Prelude + In-window phases

### Status: COMPLETE

### What was implemented

**`NotificationDecider.kt`:**
- Added `decideUvWarning()` — pure UV Warning decision logic with Prelude and In-window phases.
- Prelude: currentUV < 6 AND next forecast hour UV >= 6.
- InWindow: currentUV >= 6 (fallback when Prelude was missed).
- Guards: `uvWarningEnabled`, `uvWarningDisabledOn == today`, `lastUvWarningOn == today`
  (once-per-day dedup; Worse News re-fire added in the next slice).
- Helper `buildWarnedAbout()` captures peak, firstHighHour, highHours from all high-UV entries.
- Helper `buildUvWarningContent()` builds German notification text for each phase.
- `decide()` now calls both `decideDailyForecast()` and `decideUvWarning()`.

**`NotificationHistoryStore.kt`:**
- Extended `migrate()` to fold legacy hourly + transition SharedPreferences into the umbrella:
  - `last_hourly_sent_time` (Long ms) → `lastUvWarningAt` + `lastUvWarningOn`
    (if sent today, dedup blocks immediate re-fire).
  - `hourly_disabled_date` (String) → `uvWarningDisabledOn`.
  - `last_transition_warned_hour` + `last_transition_warned_date` → `lastUvWarning`
    with peak=6.0f (conservative), highHours={warnedHour}.
    If transition was today → `lastUvWarningOn = today` to block re-fire.
- Added four new legacy constants for the new migration paths.

**`NotificationDispatcher.kt`:**
- `buildNotification()` now iterates `decision.actions`.
- For `Action.DisableUvWarningsToday`, adds "Warnungen heute deaktivieren" button whose
  PendingIntent broadcasts to `NotificationActionReceiver.ACTION_DISABLE_UV_WARNINGS`.

**`NotificationActionReceiver.kt`:**
- Replaced `ACTION_DISABLE_HOURLY` + direct SharedPreferences writes with
  `ACTION_DISABLE_UV_WARNINGS` + `historyStore.markUvWarningDisabledToday()` via goAsync coroutine.
- No SharedPreferences calls remain in the receiver.

**`HourlyUpdateWorker.kt`:**
- Deleted inline methods: `checkAndSendHourlyWarning`, `checkAndSendTransitionWarning`,
  `sendHourlyWarning`, `isHourlyDisabledToday`, `isHourlyNotificationEnabled`,
  `hasNotificationPermission`.
- `doWork()` now: fetch forecast → `historyStore.snapshot()` → `NotificationDecider.decide()`
  → dispatch + record each decision.
- Widget update path (only on `shouldFetchNew`) preserved unchanged.

**`AndroidManifest.xml`:**
- Updated `NotificationActionReceiver` intent-filter action from `DISABLE_HOURLY`
  to `DISABLE_UV_WARNINGS`.

**Note on notification ID 3:**
No code path in the new module emits notification ID 3. The legacy
`checkAndSendTransitionWarning` (which called `notify(3, ...)`) has been deleted from
`HourlyUpdateWorker`.

**Tests:**
- `NotificationDeciderTest` — 5 new UV Warning tests: Prelude fires, InWindow fires,
  silent when disabled in settings, silent when disabled today, silent when sent today.
  `historyWith()` helper defaulted to `uvWarningEnabled = false` to isolate Daily-channel
  tests from UV Warning interference.
- `NotificationHistoryStoreTest` — 4 new migration tests: hourly timestamp/disabled date,
  lastUvWarningOn set to today when hourly was sent today, transition keys → lastUvWarning.
- `NotificationDispatcherTest` — 1 new UV Warning test: notification ID 2, correct title,
  action button present.

## Issue #8 — Worse News re-fire on forecast updates

### Status: COMPLETE

### What was implemented

**`NotificationDecider.kt`:**
- Added `internal fun worseNews(previous: WarnedAbout?, current: WarnedAbout, now: LocalDateTime): Boolean`.
  Decision-locked predicate: `previous == null` → true; `current.peak > previous.peak` → true;
  `current.firstHighHour < previous.firstHighHour` → true; any `current.highHours` hour
  `>= now.hour` not in `previous.highHours` → true; otherwise false.
- Modified `decideUvWarning()`: moved `highForecasts`/`warnedAbout` computation before the
  once-per-day dedup guard. When `lastUvWarningOn == today`, calls
  `worseNews(history.lastUvWarning, warnedAbout, now.toLocalDateTime())`; only suppresses
  if `worseNews` is false. The unconditional `uvWarningDisabledOn == today` block is unchanged.
- Added `import java.time.LocalDateTime`.

- Updated `historyForUvWarning()` to accept `lastUvWarning: WarnedAbout? = null`.
- Updated existing "silent when sent today" test to supply a matching `lastUvWarning` so
  `worseNews` correctly returns false (previously `null` which now triggers a re-fire).
- Added `forecastWithHoursAt(nowHour, hourUVs)` helper for multi-hour forecast construction.
- Added `nowAt(hour)` helper for `LocalDateTime` in `worseNews` direct tests.
- 6 `worseNews` direct tests: null previous → true; identical → false; higher peak → true;
  new high hour after now → true; earlier firstHighHour → true; shrunk window → false.
- 4 `decide()` re-fire tests: re-fires on higher peak; re-fires on new hour after now;
  re-fires on earlier firstHighHour; stays silent on shrunk window.
- 1 interaction test: user disabled today, forecast worsened → still silent.

## Issue #9 — Clean up legacy notification SharedPreferences keys

### Status: COMPLETE

### What was implemented

**`NotificationHistoryStore.kt`:**
- Added `purgeLegacyKeys()` private method: removes the six legacy keys from `uv_notifications`
  SharedPreferences via a single `edit().remove(...).apply()` chain:
  `daily_sent_date`, `daily_sent_timestamp`, `last_hourly_sent_time`,
  `hourly_disabled_date`, `last_transition_warned_hour`, `last_transition_warned_date`.
- `record()` calls `purgeLegacyKeys()` at the end, after writing to the umbrella. Since `record()`
  always writes at least one umbrella value, this satisfies the "after umbrella has at least one
  written value" trigger. Subsequent calls are idempotent (removing absent keys is a no-op).
- `uv_app_settings` keys (`daily_notification_enabled`, `hourly_notification_enabled`) are not touched.
- Updated legacy key comment from "left in place" to "purged from uv_notifications on first record()".

**`NotificationHistoryStoreTest.kt`:**
- Added `import java.time.Instant` for the new test helper.
- 3 new tests (Issue #9 section):
  - `record deletes six legacy keys from uv_notifications` — writes all 6 legacy keys, calls
    `record()`, asserts none remain; also verifies umbrella is still readable.
  - `snapshot alone does not touch legacy keys` — confirms legacy keys survive multiple
    `snapshot()` calls when no `record()` has been called.
  - `record does not touch settings keys in uv_app_settings` — seeds both settings keys, calls
    `record()`, verifies both keys are still present with their original values.

## Issue #11 — UV Risk classifier: single owner of High UV / Very High UV thresholds

### Status: COMPLETE

### What was implemented

**New module `com.uvindex.app.uv.UvRisk` (`app/src/main/java/com/uvindex/app/uv/UvRisk.kt`):**
- `enum class UvRisk { None, Moderate, High, VeryHigh }` — ordinal ordering enables `>=` comparisons.
- `classifyUvRisk(uvIndex: Double): UvRisk` — pure top-level classifier; thresholds ≥ 8.0 → VeryHigh, ≥ 6.0 → High, ≥ 3.0 → Moderate, else None.
- `isHigh(): Boolean` extension — true for High and VeryHigh.
- `isVeryHigh(): Boolean` extension — true only for VeryHigh.
- No Android imports; pure Kotlin.
- Package `com.uvindex.app.uv` chosen so `notification` depends on `uv`, not the reverse.

**`NotificationDecider.kt` — all 6.0 / 8.0 literals replaced:**
- Phase detection: `currentUV < 6.0` / `>= 6.0` → `!currentRisk.isHigh()` / `currentRisk.isHigh()` via `classifyUvRisk`.
- `highForecasts` filter: `it.uvIndex >= 6.0` → `classifyUvRisk(it.uvIndex).isHigh()`.
- InWindow `highHours` filter: same pattern.
- InWindow `veryHigh` filter: `it.uvIndex >= 8.0` → `classifyUvRisk(it.uvIndex).isVeryHigh()`.
- `buildHighUVDescription` very-high filter: `it.uvIndex >= 8` → `classifyUvRisk(it.uvIndex).isVeryHigh()`.
- `buildHighUVDescription` high-only filter: `it.uvIndex in 6.0..<8.0` → `classifyUvRisk(it.uvIndex) == UvRisk.High`.
- `WeatherRepository.findHighUVTimeSlots` (4.0 threshold, chart highlighting) left unchanged per spec.
- `UVColorHelper` left unchanged per spec.

**`CONTEXT.md` — forward-reference removed:**
- High UV and Very High UV entries now point to `classifyUvRisk` in `com.uvindex.app.uv.UvRisk`.
- "see deepening opportunity #1" removed.

**`UvRiskTest.kt` (`app/src/test/java/com/uvindex/app/uv/UvRiskTest.kt`):**
- 9 pure JVM tests covering: None range, Moderate range, High boundary (6.0), High mid-range, VeryHigh boundary (8.0), VeryHigh above 8.0, isHigh() for High/VeryHigh, isHigh() false for None/Moderate, isVeryHigh() exclusive to VeryHigh.
